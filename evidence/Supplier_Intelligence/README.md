# Supplier_Intelligence | Unsupervised machine learning
Synthetic data only. Source CSVs unchanged. Executed Python workflow, fixed seeds. No delivery outcomes in fitting. Supplier aggregates use training order-time predictors; retrospective profile outcome means use receipts before 2024-04-15 (all 6,000). Supplier profiles weight suppliers equally; order counts are separate. Eight indicators standardised; PCA is descriptive, K-means and Ward use all eight standardised features. Five PCs explain 83.94%. K=2 selected for highest silhouette among k=2–7 with minimum five suppliers per cluster; silhouette 0.292, Ward agreement ARI 0.897, mean subsample stability ARI 1.000 (40 samples of 80% suppliers). These are internally stable but modestly separated. Cluster 1: 34 default sea suppliers; cluster 2: 86 default road suppliers. Segment reflects transport geography, not independent quality or causal risk. Supplier-level mean observed late rates 73.00% and 49.81%, respectively.
Isolation Forest trained on 6,000 orders, 300 trees, 5% contamination (assumed review capacity, not measured anomaly prevalence). Twelve features including route-relative planned lead and congestion deviations (training medians; mode/global fallbacks) and inventory coverage ratio. Flags: 300 training, 83 validation, 102 test, 57 scoring. Positive score indicates anomaly, not probability of delay. No verified anomaly labels. Test predictors scored only, no test outcomes used for tuning. Replay script verified scoring scores and flags. Unknown suppliers receive missing cluster IDs; review manually. No raw data included in this package. No R execution or Shiny integration performed.
## Use
Install requirements in Python environment. Run `python Supplier_Intelligence.py data Supplier_Intelligence` with original CSVs in data. For future uploads `python score_new.py input.csv output.csv` from this folder; use trusted joblib only. A production upload validator must additionally enforce full data dictionary types, ranges, categorical domains, dates and access controls. Current script validates minimum required columns, missingness, duplicate keys, positive denominators, finite model inputs. Shiny may read score CSVs or call a separately hosted Python scoring service; native R model reproduction is future work.
## Leakage warning for Predictive_Modelling
Do not merge frozen full-training supplier cluster or in-sample anomaly score into historical training orders for supervised evaluation. They reflect information from later training dates or models fitted on those rows. Use rolling/expanding-window out-of-time features with strict historical cutoff if incorporating these in supervised models; otherwise exclude them and use only original as-of features. Test outcome summaries previously published in Exploratory_Analysis; no test outcome tuning in Supplier_Intelligence. Prefer fresh holdout if strict independence needed.
